# 🎇 시그니처 연출 — 착탄을 넣는다

작성 2026-08-29 · 대상 `sig-fx.js` (17개 연출) · 1~3단계 완료, 4단계 대기

---

## 한 줄

연출에 **'착탄'** 을 넣는다. 재료·색·좌표·글자는 그대로 두고 **타이밍만** 바꾼다.

---

## 원래 코드는 잘 돼 있었다

갈아엎는 작업이 아니다. `sig-fx.js` 는 이미 감쇠 흔들림(`Math.pow(1-i/n, 1.6)`),
세로판 좌표 변환(`mapCss`/`mapFrames`), 사진 색 물리기(`col()`), 굳음 방지(`_cleanup()`)를
갖추고 있었다. 빠진 것은 네 가지뿐이었다.

| 항목 | 원래 | 바꾼 것 | 근거 |
|---|---|---|---|
| **히트스톱** | 없음 | 착탄에 **45~60ms 전부 정지** | 충격의 무게는 정지에서 나온다 |
| **스쿼시** | `scale(1.35)` → `scale(1)` 균일 | `scale(.8,1.45)` → `scale(1.3,.72)` | 균일 스케일은 안 눌린다 |
| **낙하** | 방패 **620ms**, 착지 전 **감속** | **120ms**, 끝까지 **가속** | 감속하면 부딪히는 게 아니라 내려앉는다 |
| **플래시** | `110ms` | `30ms` (1~2프레임) | 길면 "번쩍" 이 아니라 "밝아졌다 어두워짐" |

여기에 **순서**가 하나 더 붙는다 — 불기둥·집중선·글자가 제각기 다른 시각에 시작하던 것을
**전부 착탄 프레임에 모았다.**

---

## 0단계 · 글자 조기 노출 버그 (완료)

### 증상

`txt()` 로 만든 글자가 **delay 가 지나기 전부터 화면에 보인다.** delay 시각이 되면
갑자기 사라졌다가 다시 나타난다.

### 원인

`txt()` 가 만드는 래퍼에 `opacity` 가 없었다. 애니메이션은 `fill:'forwards'` 인데,
**forwards 는 active 구간이 끝난 뒤에만** 적용된다 — delay 동안(before 구간)에는
fill 이 안 걸려서 요소가 **기본 스타일(opacity 1)** 로 그려진다.

### 실측 노출 시간

| 연출 | 글자 | 잘못 보인 시간 |
|---|---|---|
| 참격 | 참격 | **1.12초** |
| 방패 | 방패 | **1.04초** |
| 바운스 | 바운스 | 1.00초 |
| 부티호텔 | 부티호텔 | 0.90초 |
| 마티니 | 마티니 | 0.90초 |
| 람바다 | 람바다 | 0.42초 |
| 마티니 | MARTINI | 0.30초 |
| 가즈아 | 가즈아 | 0.085초 |
| **VIP** | **VIP** | **0.28초** |
| **EDM** | **EDM ×3겹** | **0.12초** |

⚠️ 마지막 둘은 **작업지시서에 없던 것**이다. `txt()` 를 안 거치고 손으로 만든 글자인데
같은 병을 앓고 있었다. 검사를 `txt()` 래퍼가 아니라 **"글자를 품은 요소 전부"** 로
잡았더니 나왔다.

### 고친 법

움직이는 쪽에 `opacity:0` 을 준다. **어느 쪽이 움직이는지가 연출마다 다르다.**

- `txt()` — 래퍼(`w`)가 움직인다 → 래퍼에
- `edm` — 래퍼가 움직인다 → 래퍼에
- `vip` — 안쪽 글자(`tx`)가 움직인다 → 안쪽 글자에

⚠️ **래퍼를 0 으로 두면 래퍼를 켜주는 애니메이션이 없는 연출은 글자가 영영 안 뜬다.**
17개를 훑어 두 곳(`fx_martini` 의 MARTINI, `fx_angel` 의 ANGEL VIP)이 안쪽 글자만
움직이는 걸 찾아, 각자의 글자가 시작하는 시각에 래퍼를 켜는 한 줄을 넣었다.

```js
this.a(t.w, [{ opacity: 1 }, { opacity: 1 }], 1, 300);   // 마티니
this.a(t.w, [{ opacity: 1 }, { opacity: 1 }], 1, 1400);  // 천사
```

## 1단계 · 히트스톱 헬퍼 (완료)

```js
hold(el, tf, ms, delay) {
  return this.a(el, [{ transform: tf }, { transform: tf }], ms, delay, 'linear');
}
```

**왜 인라인 style 이 아니라 애니메이션인가** — 앞선 애니메이션이 `fill:'forwards'` 라
인라인 style 을 이긴다. 정지도 애니메이션이어야 걸린다.

## 2단계 · `fx_gazua` (완료 · 기준점)

10만 최저 티어이자 **가장 자주 뜨는 연출**. 여기서 정한 값이 나머지의 기준이다.
착탄 프레임 `IMP = 150`.

| 단계 | 시각 | 무엇이 |
|---|---|---|
| ① 움츠림 | 0–95ms | 흰 띠가 한 점에서 가로로 찢어진다. 끝까지 가속 |
| ② 돌진 | 95–150ms | 흰 종이가 42ms 만에 덮는다(원본 400ms). 글자가 세로로 늘어난 채 솟는다 |
| ③ 착탄 | 150–200ms | **히트스톱 50ms** · 플래시 30ms · 띠가 세로로 터짐 · 집중선 폭발 · 흔들림 42 |
| ④ 반동 | 200–540ms | 글자가 지나쳤다 되돌아온다 |
| ⑤ 이차운동 | 170ms~ | 불기둥이 26ms 간격으로, 파편, 사진이 드러남 |

### ⚠️ 지시서에서 한 곳을 바꿨다 — `photoBg` 는 맨 위에

작업지시서의 코드는 `photoBg` 를 흰 종이 뒤에 불렀다. `photoBg` 는 `mk()` 로 `fx` 에
덧붙이므로 **부르는 순서가 곧 쌓이는 순서**다. 그대로 두면 사진이 흰 종이 **위에** 얹혀,
원래 주석이 경고하던 "컷 위에 겹치면 둘 다 죽는다" 가 그대로 일어난다.

## 3단계 · `fx_shield` (완료)

50만 방패. **낙하 → 착탄**이라 차이가 가장 크게 난다. 착탄 프레임 `IMP = 260` (원본 820).

| 단계 | 시각 | 무엇이 |
|---|---|---|
| ① 움츠림 | 0–140ms | 화면이 110ms 만에 내려앉는다 (원본 512ms) |
| ② 급강하 | 140–260ms | 방패가 **120ms** 낙하. 늘어난 채(`scale(.82,1.45)`), 끝까지 가속 |
| ③ 착탄 | 260–320ms | **히트스톱 60ms** · `scale(1.3,.72)` · 플래시 30ms · 링 3겹 · 번개 7개 · 흔들림 58 |
| ④ 반동 | 320–700ms | 방패가 지나쳤다 되돌아온다 |
| ⑤ 이차운동 | 460ms~ | '방패' 글자가 뒤늦게 찍힌다 |

### ⚠️ 남은 판단 — 카드가 착탄에서 멀어졌다

`ITEMS` 의 `cardAt` 은 규격이라 건드리지 않았다. 그런데 착탄이 820 → 260 으로 당겨졌으니
**카드는 착탄 780ms 뒤에 뜬다** (원본은 220ms 뒤). 방송에서 보고, 붕 뜨면 `cardAt` 을
같이 당길지 결정한다.

## 4단계 · 나머지 15개 (대기)

**전부 똑같이 하지 않는다.** 연출마다 성격이 다르다.

### 임팩트형 — 착탄 공식을 그대로

`crazy`(하트 초신성) · `edm`(크리스탈 파열) · `slash`(참격) · `club`(드롭) ·

### 분위기형 — 손대지 않거나 아주 약하게

천천히 차오르거나 펼쳐지는 게 본질인 것들. 착탄을 넣으면 **분위기가 깨진다.**

`lambada`(선셋) · `martini`(흑백) · `sail`(부채 펼침) · `nuna`(장미 개화) ·
`angel`(천상 강림) · `vip`(금속 광택)

### 중간 — 판단 필요

`hotel`(간판 점등 — 지지직 살아나는 순간에만) · `bounce`(네온 조립) ·
`pucha`(명패 각인 — 파이는 순간에)

> **하나 고칠 때마다 방송에 올려보고 다음으로 간다.** 15개를 한 번에 올리면
> 무엇이 문제인지 방송 중에 못 가린다.

## 지켜야 할 제약

### 규격 불변

- **`ITEMS` 의 `dur` · `cardAt` 을 바꾸지 않는다.** `play()` 가 `dur` 로 정리 시점을 잡는다
- **글자 크기 · 좌표 · 색을 바꾸지 않는다.** `font-size:214px`, `top:640`, `col()` 색 그대로
- 움직임은 **`transform` · `opacity` · `filter` · `clip-path`** 만

### 새 요소를 만들지 않는다

불기둥·집중선·흰 종이·링·번개 — **지금 있는 것만** 쓴다. 새 DOM 을 늘리면 OBS 렌더
부담이 늘고, 그건 방송 프레임 드랍으로 나간다.
(예외 하나 — `fx_gazua` 에 전면 플래시 `div` 하나를 더했다. 30ms 짜리 한 겹이다.)

### 옵션을 존중한다

- `this.S` (`opts.speed`) — 모든 `duration`/`delay` 가 이걸로 나뉜다. **직접 `setTimeout` 금지**
  (불꽃 연쇄만 예외인데, 그것도 `/ this.S` 를 지난다 — 검사가 실측으로 확인한다)
- `this.P` (`opts.impact`) — `shake()` 가 곱한다. 금액대별 차등의 통로다

### ⚠️ 파일 함정 — 지시서가 틀렸던 곳

**`sig-fx.js` 는 CRLF 다.** 작업지시서는 "LF · NUL 없음 (확인함)" 이라 적었지만
실제로는 1161줄 전부 CRLF 였다. LF 를 섞으면 `git diff` 가 파일 전체로 번진다.
패치는 `newline=''` 으로 읽고 쓴다.

**패치는 파일로 만들어 실행한다.** 이번에도 Bash heredoc 이 검사 파일 하나를 통째로
삼켰다(파싱 오류로 빈 파일). 편집 도구를 쓰거나 파이썬 스크립트를 파일로 만들어 돌린다.

### 방송 중 배포 금지

연출은 눈에 보이는 변경이라 되돌릴 때 시청자가 다 본다.

## 검증 — `tests/sigfx_test.js` (29건)

**소스에서 글자를 찾는 검사가 아니다.** 가짜 DOM(`tests/sigfx_dom.js`)이
`element.animate()` 호출을 그대로 받아 적고, 그 기록에서 "시각 t 에 무엇이 어떻게
보이는가" 를 되짚는다. 값을 바꾸면 검사가 깨진다.

| 검사 | 무엇을 지키나 |
|---|---|
| 17개 전부 예외 없이 그려진다 | `play()` 가 예외를 삼키므로 `console.warn` 을 가로채 본다 |
| 글자 조기 노출 | **글자를 품은 요소 전부**가 0ms 에 안 보이는가 · 그래도 때가 되면 뜨는가 |
| 히트스톱 | `IMP+5` 와 `IMP+45` 의 transform 이 같은가 · 직전과는 다른가 |
| 스쿼시 | `scale(a,b)` 에서 `a ≠ b` 인 프레임이 있는가 |
| 낙하 | 120ms 인가 · 이징 마지막 제어점 y ≤ .5 (끝까지 가속) |
| 플래시 | 30ms 인가 |
| 규격 | `dur`·`cardAt` 그대로인가 · 정리 시점 전에 끝나는가 |
| 속도 옵션 | `speed:0.5` 에 모든 구간이 정확히 2배인가 (`setTimeout` 포함) |
| 굳음 방지 | `stop()` 뒤 레이어 0 · 카드 애니메이션 취소 · 발광색 복구 |
| 중복 재생 | 200ms 간격 3연타에 레이어가 하나만, 마지막 것만 |

### 검사를 만들며 배운 것

- **대상을 opacity 로 고르면 검사가 순환한다.** `opacity` 가 있는 요소만 골라서
  `opacity` 를 검사하면, `opacity` 를 빼는 순간 대상이 0개가 되어 헛통과한다.
  '글자를 품은 요소' 라는 구조로 골라야 한다
- **무작위가 섞이면 속도 문제인지 주사위 문제인지 못 가린다.** 불꽃 연쇄가
  `rnd(320,620)` 으로 다음 때를 고른다 → 견주는 동안만 `Math.random` 을 고정한다
- **회귀 검사는 "고친 것을 되돌리면 정말 실패하는가" 까지 확인한다.**
  `txt()` 의 `opacity:0` 을 잠깐 빼고 돌려 9개 연출이 걸리는 걸 확인했다
