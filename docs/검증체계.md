# ✅ 검증 체계

## 원본은 저장소 `tests/` 다

검사 파일은 원래 세션 임시 폴더(스크래치패드)에만 있었는데, **2026-08-27 시스템이 임시
폴더를 정리하면서 검사 두 개가 증발했다**(세션 기록에서 복원했다). 그날로 전부를
`tests/` 로 옮겼다. 러너(`tests/runall.py`)는 시작할 때 저장소에서 검사를 샌드박스로
동기화하므로, **검사를 고치면 저장소 쪽을 고치면 된다.**

## 돌리는 법

```bash
# 스크래치패드(세션 임시 폴더)에 복사해 두고 돌린다 — 샌드박스 DB·서버가 거기 생긴다.
# 저장소 안에서 직접 돌리면 임시 DB 가 저장소를 어지럽히므로 하지 않는다.
python runall.py
```

러너는 검사마다 서버를 **깨끗한 DB 로 다시 띄운다**. 이전 검사가 남긴 상태(방송 중 여부,
큐, 점수)가 다음 판정을 뒤집는 일이 실제로 여러 번 있었다. 샌드박스는 두 벌:

| | lt2 (포트 5177) | pausetest (포트 5199) |
|---|---|---|
| 기동 | `boot.py` (server.py 그대로) | `boot_sig.py` (Supabase 만 가짜로 갈아끼움) |
| 용도 | 부하·무결성·충돌 | 시그니처·게임·점수 등 기능 검사 |

주의: 서버는 `0.0.0.0` 에 붙는다 — 포트 소유자를 찾을 때 주소를 가리지 말 것
(127.0.0.1 로만 찾다가 "기동 실패" 오판 + 서버 6개가 쌓인 사고가 있었다).
러너 두 개를 동시에 돌리지 말 것(뒤에 뜬 쪽이 앞의 서버를 죽인다).

## 검사 작성 규칙

- 실행 검사가 기본. 실측으로 확인 못 하는 "다시 갈라지면 안 되는 것"만 정적 검사
  (예: 나눠주기 식이 두 파일에서 글자까지 같은가)
- 화면 JS 를 검사할 땐 **파일에서 꺼낸 진짜 코드를 node 로** 돌린다
  (파이썬 round 는 5를 짝수로 보내 거짓 통과가 난다)
- **대상을 검사할 속성으로 고르지 않는다.** opacity 가 있는 요소만 골라 opacity 를
  검사하면, opacity 를 빼는 순간 대상이 0개가 되어 헛통과한다 (`sigfx_test.js` 에서 겪음)
- **고친 것을 되돌리면 정말 실패하는지**까지 확인하고 검사를 마친다
- API 할당량(NVIDIA 분당 30회)을 검사가 먹으면 안 된다 — AI 검사는 정적,
  실제 호출 검증은 손으로 따로
- 통과/실패 집계 줄(`통과 N / 실패 M`)을 반드시 찍는다 — 러너가 그걸 읽는다
- 새 기능 = 새 검사 + 러너 등록. 검사 없이 커밋하지 않는다
