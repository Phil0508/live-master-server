# 🎨 편집기 (admin)

방송 화면 위젯 17개의 위치·크기를 끌어서 잡는 화면. 저장은 `/api/layout`
(dict 검증 + 임시파일 + fsync + 원자적 교체).

## 소스 목록 — OBS 방식 (2026-08-27)

**문제**: 켜진 위젯이 캔버스에 전부 펼쳐져 겹치고, 원하는 걸 집기 어려웠다.

**해결**: 사이드바 맨 위에 위젯 목록. 줄을 누르면 선택(캔버스 강조 + 크기 조절판),
캔버스 클릭과 양방향 동기화.

- **👁 눈** — *편집 화면에서만* 보이기/숨기기. 겹쳐서 방해되는 위젯을 치워두고 편집
- **🔒 잠금** — 캔버스에서 안 집힘(pointer-events). 목록에서는 선택 가능
- **"선택한 것만 또렷하게"** — 나머지는 투명도 0.22 로 깔림
- 눈·잠금은 localStorage(`edvis:` / `edlock:`) — 브라우저가 기억

### 👁 가 방송을 끄지 않는 이유 (중요한 설계 결정)

OBS 의 눈은 방송 출력까지 끈다. 여기서 그렇게 하면 **방송 표시 스위치가 두 군데**가 된다
— 방송 표시는 조종실 스위치(match.active, slot_enabled, dicegame.enabled …)가 이미
정하고 있고, 위젯마다 그 스위치의 필드가 다 다르다. 편집기 눈이 그걸 또 만지면
"편집기에서 껐는데 왜 방송에 나가?" 류의 사고와 쓰기 경합이 생긴다.

그래서: **눈은 편집 화면 전용**, 방송 여부는 목록의 "방송 꺼짐" 표찰로만 보여준다.
`edLive(id, on)` 이 서버 상태를 `dataset.live` 에 기억하고, 실제 표시는 `srcApply()` 가
눈 기준으로 정한다. 눈을 아직 안 만진 위젯은 방송 상태를 따라간다(첫 화면이 안 어지럽게).

**부수 효과(개선)**: 방송에 꺼져 있는 위젯도 편집기에서 눈만 켜면 자리를 미리 잡을 수
있다. 전에는 꺼진 위젯은 편집 자체가 불가능했다.

## 드래그 성능의 역사 (같은 실수 방지용)

1. **매 프레임 `offsetWidth` 를 읽어 강제 reflow** — 크기는 드래그 시작 때 한 번만 잰다.
   이동은 `translate3d` + rAF, 확정(left/top)은 손을 뗄 때 한 번
2. **끄는 내내 격자(10px) 반올림** — 캔버스가 1/3 배라 화면에서 3.3px 씩 계단으로 뛰었다
   (실측: 마우스 100번에 35번만 따라옴). 격자는 **놓을 때 한 번만**, 안내선에 붙은 자리는
   다시 반올림하지 않는다
3. **정렬선 후보 33개가 사방에서 끌어당김** — 나란히 놓인(다른 축이 겹치는) 위젯하고만
   맞춘다(후보 6~21개). 실측 100번 중 68~88번으로 개선
4. 클릭만 해도 격자로 밀리던 것 — 실제로 끌었을 때(dragMoved)만 격자 확정
5. SSE 갱신은 드래그 중 미뤄뒀다가(pendingState) 손을 떼면 그린다

## 앞으로 할 만한 것

- 소스 목록에서 끌어서 겹침 순서(z-index) 바꾸기 — OBS 처럼
- 위젯 여러 개 같이 선택해 한꺼번에 이동
- 배치 프리셋(평소용/대결용/이벤트용) 저장·전환
