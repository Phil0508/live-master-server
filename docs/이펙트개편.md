# 🎆 이펙트 개편 계획

작성 2026-08-30 · 대상 `sig-fx.js` (17개 연출) · 착수 전

> 시작은 두 가지였다.
> ① 유튜브 라이브는 화면 아래에 채팅이 깔린다 — **아래쪽 연출이 안 보인다**
> ② **"내가 돈을 쐈구나"** 싶게, 훨씬 더 반짝이게
>
> 재보니 그 앞에 더 큰 게 있었다. **연출의 절반이 화면 밖에 그려지고 있다.**

방송은 **1080×1920 세로(쇼츠)로만** 나간다. 시청자가 가로로 볼 방법이 없으므로
이 판 하나만 맞추면 된다.

## 0. 방송에서 겪은 것 → 원인

사장님이 방송에서 본 것 두 가지가 정확히 두 개의 버그를 가리킨다.

### "가즈아도 밑에 나오고 너무 잠깐 나와서 안 보이더라"

`txt()` 가 세로 좌표를 `KY` 로 곱해 `mk()` 에 넘기는데, `mk()` 안의 `mapCss()` 가
**또** 곱한다. `KY² = 3.16배`.

```js
const w = this.mk(fx, '...top:' + this._n(top, this.KY) + 'px;...');
//                            └── 여기서 한 번    └── mk→mapCss 가 또 한 번
```

'가즈아' 는 `top:640` 으로 설계됐다. 나와야 할 자리는 1138(59%)인데 **2023** 에
앉는다. 판은 1920 이고 `overflow:hidden` 이라 **안 보인다.**

그럼 왜 "밑에 나오긴 했다" 인가 — 퇴장 애니메이션이 `translateY(-190px)` 로
위로 민다. 이게 KY 로 접혀 **-338px**. 그래서 2023 → **1685(88%)** 까지 올라온다.
**사라지는 마지막 0.5초 동안만, 화면 맨 아래에서, 투명해지면서 스친다.**

사장님이 본 그대로다.

| 연출 | 글자 | 설계값 | 나와야 할 자리 | 실제 |
|---|---|---|---|---|
| 가즈아 | 가즈아 | 640 | 1138 (59%) | **2023** |
| 부티호텔 | 부티호텔 | 700 | 1244 (65%) | **2212** |
| 바운스 | 바운스 | 720 | 1280 (67%) | **2276** |
| 마티니 | 마티니 | 660 | 1173 (61%) | **2086** |
| 50만 방패 | 방패 | 830 | 1476 (77%) | **2623** |
| 74번 알림 | 참격 | 800 | 1422 (74%) | **2528** |
| 엔젤 VIP | ANGEL VIP | 820 | 1458 (76%) | **2592** |

`mk()` 로 직접 만든 글자(EDM · VIP · BOUNCE · HOTEL · MVP · 푸차)는 한 번만
접히므로 멀쩡하다. **그래서 어떤 연출은 글자가 나오고 어떤 연출은 안 나온다.**

### "람바다도 나무라던가 요소들이 1도 안 보였어"

이게 더 크다. **가로 좌표가 잘린다.**

연출은 **1920 폭 가로** 기준으로 짜여 있고, `_fit()` 이 세로판으로 접는다.

```js
this.KS = (W / 1920) * (portrait ? 1.6 : 1);        // 0.5625 × 1.6 = 0.9
_x(v) { return this.W / 2 + (v - 960) * this.KS; }  // 가운데 기준으로 접는다
```

세로판은 폭이 좁아 그대로 줄이면 글자가 작아진다. 그래서 **1.6배 키웠다.**
그런데 그 1.6배가 **크기만이 아니라 가로 위치에도** 걸린다.

결과: 설계 폭 1920 이 1728 로 펴져 1080 판 가운데에 놓인다 → **-324 ~ 1404**.
**설계의 가운데 360~1560 구간(62%)만 화면에 남고 양옆 38%는 잘려 나간다.**

람바다 야자수는 화면 양 끝에 세우려고 `left:-40` 과 `left:1960` 으로 박아뒀다.

| | 설계 | 지금 | |
|---|---|---|---|
| 왼쪽 야자 | -40 | **-360** | 화면 왼쪽 밖 |
| 오른쪽 야자 | 1960 | **1440** | 화면 오른쪽 밖 (판은 1080) |
| 잎사귀 10장 | 좌우 끝 | 밖 | 전부 안 보임 |

### 연출별 피해 — 가로로 화면 밖에 나간 요소

| 연출 | 밖으로 나간 것 | 전체 | 비율 |
|---|---|---|---|
| **부티호텔** | **35개** | 43 | **81%** |
| 푸차 | 6개 | 9 | 67% |
| 마티니 | 11개 | 18 | 61% |
| **람바다** | **12개** | 24 | **50%** |
| VIP | 8개 | 26 | 31% |
| 출항 | 6개 | 26 | 23% |
| 클럽음악 | 12개 | 60 | 20% |
| 가즈아 | 4개 | 20 | 20% |
| 누나누나 · 천사 · 바운스 | 1~3개 | | |

**부티호텔은 사실상 아무것도 안 보이는 연출이다.** 네온관 43개 중 35개가 밖에 있다.

## 1. 좌표계를 다시 세운다 ← 1단계

세 가지(세로 두 번 접힘 · 가로 잘림 · 채팅 안전지대)가 **전부 같은 자리**의 문제다.
따로 고치면 세 번 흔들린다. **한 번에 한다.**

### 새 규칙

```
설계 공간 : 1920 × 1080 (가로)        연출 코드는 이대로 둔다
방송판    : 1080 × 1920 (세로)

가로 위치 : x' = x × (W/1920)                    ← 1920 폭이 1080 에 정확히 들어간다
세로 위치 : y' = 안전위 + y × (안전높이/1080)      ← 1080 높이가 안전지대에 들어간다
크기·글자 : s' = s × KS                          ← 따로 키운다. 작아지지 않게
가로 거리 : translateX × (W/1920)                 ← 위치와 같은 배율
세로 거리 : translateY × (안전높이/1080)
```

**핵심은 "크기 배율"과 "위치 배율"을 갈라놓는 것이다.** 지금은 하나(KS)로 둘 다
하고 있어서, 글자를 키우려고 올린 1.6배가 위치까지 벌려 화면 밖으로 밀어낸다.

```js
_fit(stageEl) {
  const W = stageEl.clientWidth || 1920, H = stageEl.clientHeight || 1080;
  this.W = W; this.H = H;

  // 유튜브 세로 라이브는 위에 채널줄, 아래 절반에 채팅이 깔린다 (실측 근거는 2장)
  this.SAFE_TOP = 0.06;
  this.SAFE_BOT = 0.50;

  this.KX = W / 1920;                                     // 가로 위치·거리
  this.YT = H * this.SAFE_TOP;                            // 안전지대 시작
  this.KY = H * (this.SAFE_BOT - this.SAFE_TOP) / 1080;   // 세로 위치·거리
  this.KS = this.KX * (H > W ? 1.39 : 1);                 // 크기만 — 세로판에서 키운다
}
_x(v) { return +(v * this.KX).toFixed(1); }               // 가운데 기준 접기를 없앤다
_r(v) { return +(v * this.KX).toFixed(1); }
```

그리고 `txt()` 에서 미리 곱하는 것을 지운다 (한 줄).

```js
const w = this.mk(fx, '...top:' + top + 'px;...');
```

### 이렇게 되면

| | 설계 | 지금 | 바꾼 뒤 |
|---|---|---|---|
| 람바다 왼쪽 야자 | left -40 | **-360** (밖) | **-23** (화면 끝, 설계대로) |
| 람바다 오른쪽 야자 | left 1960 | **1440** (밖) | **1103** (화면 끝, 설계대로) |
| 가즈아 글자 | top 640 | **2023** (밖) | **616** (32%) |
| 방패 글자 | top 830 | **2623** (밖) | **764** (40%) |
| 참격 글자 | top 800 | **2528** (밖) | **741** (39%) |
| ANGEL VIP | top 820 | **2592** (밖) | **757** (39%) |
| MVP 글자 | top 760 | 1351 (70%, 채팅) | **710** (37%) |

### ⚠️ 크기 배율 1.39 는 눈으로 정한다

위치가 더 촘촘해지므로 지금 크기(1.6배)를 그대로 두면 요소끼리 겹칠 수 있다.
1.39 는 **세로 배율과 같게** 잡은 출발값이다 — 미리보기에서 17개를 훑어보고
정한다. **한 곳만 고치면 되게 둔다.**

## 2. 안전지대 — 실측

2026-08-30, 사장님 아이폰 방송 화면(1206×2622). 영상 높이(= 화면폭 × 16/9
= 2144px) 기준 % 로 환산했다.

| 구역 | 범위 | 무엇이 |
|---|---|---|
| 유튜브 채널줄 | **0 ~ 4%** | `@아이디` · 시청자수 · 좋아요 · **구독** · ⋮ |
| **안전** | **4 ~ 50%** | 아무것도 안 가린다 |
| 채팅 메시지 | **50 ~ 72%** | 최근 4~5줄이 흐른다. 긴 글이 오면 더 위까지 |
| 유튜브 고정 UI | **72 ~ 100%** | 안내배너 · 고정메시지 · 추천채널칩 · 채팅입력줄 |

1080×1920 으로 옮기면 **안전지대는 y 115 ~ 960 (높이 845px)**.

> 처음 계획서에 34% 라고 적은 것은 추측이었고 **틀렸다.** 실제로는 **절반**이다.
> 채팅 첫 줄이 53% 에 있다.

### 공식 가이드는 없다

유튜브가 내놓은 건 **Shorts 안전영역**(1080×1920 기준 888×1500, 위아래 11%씩)
뿐이고 **라이브 채팅은 계산에 안 들어가 있다.** 라이브 고객센터 문서에도
오버레이 안전영역 이야기는 없다. **사장님 화면이 유일한 정답**이다.

### 글자와 그림은 기준이 다르다

채팅은 불투명한 판이 아니라 **반투명 글자**다.

- **읽어야 하는 것** (글자·금액·이름) → **4~50% 안에만.** 글자 위 글자는 둘 다 못 읽는다
- **그림·이펙트** (불·빛·파편·링) → **72% 까지** 내려가도 된다. 채팅 뒤로 색이 번지는 건 화면이 산다
- **배경** (사진 바탕·흰 종이·플래시) → **화면 전체.** `inset:0` 은 지금처럼 안 건드린다

### 다른 위젯도 같은 문제다

- **📣 안내 전광판** — 기본 자리 `top:1680` = **87.5%**. 채팅에 완전히 묻힌다
- 계좌 위젯 · 후원순위 · 게이지도 한 번 훑는다
- 편집기에 **안전지대 선**(위 6% 실선 · 아래 50% 실선 · 72% 점선)을 그려 둔다

## 3. "돈을 쐈구나" — 무엇이 부족한가

좌표를 고치면 **원래 만들어둔 게 다 보이기 시작한다.** 그것부터 보고 나서
얹는 순서가 맞다. 하지만 그것만으로 부족한 것도 분명하다.

| 지금 | 문제 |
|---|---|
| 금액이 카드에만, 작게 | 후원자가 **자기가 얼마 쐈는지** 화면에서 못 본다 |
| 이름도 카드에만 | 연출과 사람이 따로 논다 |
| 티어가 오르면 **길어지기만** | 10만 1.8초 → 300만 7.5초. 화려함은 별로 안 는다 |
| 반짝임이 없다 | 불·네온·금속은 있는데 **빛나는** 느낌이 없다 |

### 부품 4개 — 전부 공통 함수로

17개 연출이 한 줄로 갖다 쓰고, **금액이 세기를 정한다.**

#### ① 금액 각인 `stamp(amount, at)` ← 제일 중요

착탄 프레임에 **금액이 숫자로 박힌다.** "돈을 쐈구나" 의 핵심이다.

- 큰 숫자 + `원`. 히트스톱과 같은 프레임에 눌리며 등장
- 금액대별로 색·크기가 다르다 (10만 흰금 → 300만 무지개 금속)
- 안전지대 한가운데. 카드는 나중에 뜨니 시간이 어긋나 안 겹친다

#### ② 반짝임 밭 `sparkle(n)`

4갈래 별이 안전지대 안에서 시차를 두고 깜빡인다.
`clip-path` 마름모 하나 + `opacity`/`scale` 만 — 가볍다. 개수가 티어다.

#### ③ 광택 쓸기 `sheen(el, at)`

글자·금속 위를 흰 띠가 한 번 지나간다. **VIP 에 이미 있는 기법**을 꺼내 공통으로.

#### ④ 금박 파편 `flakes(n)`

가즈아의 불티를 일반화. 회전 + 두 가지 금색 + 크기 편차.

### 티어 사다리

| 금액대 | 더할 것 |
|---|---|
| 10~20만 | 금액 각인 + 반짝임 12 |
| 30~50만 | + 광택 쓸기 + 반짝임 30 + 테두리 발광 맥동 |
| 60~100만 | + 금박 파편 + 반짝임 55 + 후원자 이름 |
| 200~300만 | + 화면 전체 점유 + 여운 + 반짝임 90 |

### ⚠️ 렌더 예산

새 요소를 늘리면 **OBS 프레임이 떨어지고 그건 방송에 그대로 나간다.**

- 한 연출이 동시에 쓰는 DOM **200개 상한** (지금 최대는 누나누나 61개, MVP 는 캔버스)
- `transform` · `opacity` · `filter` 만 움직인다
- 검사에 개수 상한을 넣어 넘으면 실패시킨다

## 4. 순서

```
1단계  좌표계 다시 세우기 (가로 잘림 + 세로 두 번 접힘 + 안전지대)
   ↓   17개가 전부 자리가 바뀐다. 미리보기로 하나씩 훑고 크기 배율(1.39) 확정
   ↓   ⏸ 방송에 올려 확인 — 없던 것들이 처음으로 보이기 시작한다
   ↓
2단계  편집기 안전지대 선 + 안내 전광판 자리 옮기기 + 위젯 훑기
   ↓
3단계  부품 4개를 엔진에 추가 (연출은 아직 안 건드림)
   ↓
4단계  가즈아·방패에 먼저 붙여 세기 정하기
   ↓   ⏸ 여기서 멈추고 판단
   ↓
5단계  나머지 15개에 티어 사다리대로
```

**1단계가 압도적으로 급하다.** 부티호텔은 81%, 람바다는 50% 가 화면 밖에서
그려지고 있다. 반짝임을 더하는 것보다 **원래 만든 게 보이게 하는 게 먼저다.**

## 5. 검증

`tests/sigfx_test.js` 에 더한다. 가짜 DOM 이 좌표를 그대로 받아 적으므로
**자로 재듯** 확인된다.

| 검사 | 무엇을 지키나 |
|---|---|
| **가로 화면 밖 금지** | 요소가 통째로 x<0 또는 x>1080 에 있지 않은가 (밖에서 들어오는 연출은 예외) |
| **세로 화면 밖 금지** | `top` 이 1920 을 넘는 요소가 없는가 — **이번 버그의 회귀 검사** |
| **두 번 접지 않는가** | 설계값 × KY = 실제값 인가 (KY² 면 실패) |
| **안전지대** | 글자가 전부 6~50% 안에 · 그림이 72% 를 안 넘는가 (17개 전부) |
| **배경은 그대로** | `inset:0` · `bottom:0` 은 여전히 화면 끝까지 가는가 |
| **DOM 예산** | 한 연출이 200개를 넘지 않는가 |
| **금액 각인** | 넘긴 금액이 화면에 그대로 나오는가 · 안 넘기면 조용히 건너뛰는가 |

미리보기(시그니처 연출 시험대)에 **안전지대 선 겹치기** 를 넣어 눈으로도 본다.
