# 🎆 이펙트 개편 계획

작성 2026-08-30 · 대상 `sig-fx.js` (17개 연출) · 착수 전

> 요청 두 가지에서 시작한다.
> ① 유튜브 라이브는 화면 아래에 채팅이 깔린다 — **아래쪽 연출이 안 보인다**
> ② **"내가 돈을 쐈구나"** 싶게, 훨씬 더 반짝이게

---

## 0. 먼저 — 글자 7개가 이미 화면 밖에 있다

계획을 짜려고 17개 연출이 화면 **어디를 쓰는지** 재보다 나왔다. 채팅에 가리는 게
문제가 아니라, **애초에 화면 안에 없다.**

### 원인

`txt()` 가 세로 좌표를 `KY` 로 곱해서 `mk()` 에 넘긴다. 그런데 `mk()` 안의
`mapCss()` 가 `top:` 을 **또** 곱한다. 결과가 `KY² = 3.16배`다.

```js
txt(fx, content, css, top) {
  const w = this.mk(fx, '...top:' + this._n(top, this.KY) + 'px;...');
  //                            └── 여기서 한 번        └── mk→mapCss 가 또 한 번
```

`txt()` 의 주석은 "top 만 옮긴다" 라고 적혀 있다. 옮기는 일이 `mapCss` 에도
있다는 걸 모르고 쓴 것이다.

### 실측

| 연출 | 글자 | 설계값 | 나와야 할 자리 | 실제 | |
|---|---|---|---|---|---|
| 가즈아 | 가즈아 | 640 | 1138 (59%) | **2023** | 화면 밖 |
| 부티호텔 | 부티호텔 | 700 | 1244 (65%) | **2212** | 화면 밖 |
| 바운스 | 바운스 | 720 | 1280 (67%) | **2276** | 화면 밖 |
| 마티니 | 마티니 | 660 | 1173 (61%) | **2086** | 화면 밖 |
| 50만 방패 | 방패 | 830 | 1476 (77%) | **2623** | 화면 밖 |
| 74번 알림 | 참격 | 800 | 1422 (74%) | **2528** | 화면 밖 |
| 엔젤 VIP | ANGEL VIP | 820 | 1458 (76%) | **2592** | 화면 밖 |
| 람바다 | 람바다 | 470 | 836 (44%) | 1485 (77%) | 너무 아래 |
| 마티니 | MARTINI | 480 | 853 (44%) | 1517 (79%) | 너무 아래 |

판은 1920 높이에 `overflow:hidden` 이다. **2023 이상은 한 픽셀도 안 보인다.**

`mk()` 로 직접 만든 글자(EDM · VIP · BOUNCE · HOTEL · MVP · 푸차)는 한 번만
접히므로 멀쩡하다. 그래서 **어떤 연출은 글자가 나오고 어떤 연출은 안 나온다.**

### 고치는 법

`txt()` 에서 미리 곱하는 것을 지운다. 한 줄이다.

```js
const w = this.mk(fx, '...top:' + top + 'px;...');
```

⚠️ 이걸 고치면 **없던 글자 7개가 갑자기 화면에 나타난다.** 그 자리가 맞는지
다시 봐야 하는데, 마침 아래 1단계가 자리를 통째로 다시 잡는 작업이다.
**둘을 같이 한다.**

## 1. 안전지대 — 채팅에 안 가리는 곳

### 지금 구조

연출은 전부 **1920×1080 가로** 좌표로 짜여 있고, `_fit()` 이 세로판으로 옮긴다.

```
y' = y * KY        (KY = 화면높이 / 1080 = 1.7778)
```

설계 좌표 0~1080 이 **화면 0~1920 전체**에 그대로 펴진다. 아래 30%도 다 쓴다.

### 바꿀 것 — 안전지대 안으로 접는다

```
y' = 안전위 + y * (안전높이 / 1080)
```

한 줄 바꾸면 **17개 연출이 전부 따라온다.** 연출 코드는 손대지 않는다.

```js
_fit(stageEl) {
  ...
  // 유튜브 세로 라이브는 위에 채널줄, 아래 절반에 채팅이 깔린다.
  // 읽어야 하는 것은 그 사이에만 둔다. (실측 근거는 아래)
  this.SAFE_TOP = 0.06;
  this.SAFE_BOT = 0.50;
  this.YT = H * this.SAFE_TOP;
  this.KY = H * (1 - this.SAFE_TOP - (1 - this.SAFE_BOT)) / 1080;
}
```

`mapCss` 의 `top` 은 `this.YT + v * this.KY` 로, `translateY`(거리)는 지금처럼
`v * this.KY` 로 둔다 — **자리는 옮기고 움직임 크기는 비율대로** 줄어든다.

---

### 실측 — 2026-08-30, 사장님 아이폰 화면 (1206×2622)

추측하지 않았다. 실제 방송 화면을 받아 재고, 영상 높이(=화면폭 × 16/9 = 2144px)
기준 % 로 환산했다.

| 구역 | 범위 | 무엇이 |
|---|---|---|
| 유튜브 채널줄 | **0 ~ 4%** | `@아이디` · 시청자수 · 좋아요 · **구독** 버튼 · ⋮ |
| **안전** | **4 ~ 50%** | 아무것도 안 가린다 |
| 채팅 메시지 | **50 ~ 72%** | 최근 채팅 4~5줄이 흐른다. 긴 글이 오면 더 위까지 올라온다 |
| 유튜브 고정 UI | **72 ~ 100%** | 안내배너 · 고정메시지 · 추천채널칩 · 채팅입력줄 |

1080×1920 판으로 옮기면 **안전지대는 y 76 ~ 960 (높이 883px)** 이다.

> **처음 계획서에 34% 라고 적은 것은 틀렸다.** 실제로는 **절반**이다.
> 채팅 첫 줄이 53% 에 있고, 메시지가 길어지면 더 올라온다.

### 두 단계로 나눈다 — 글자와 그림은 기준이 다르다

채팅은 **불투명한 판이 아니라 반투명 글자**다. 그래서:

- **읽어야 하는 것** (글자·금액·이름) → **4~50% 안에만.** 글자 위에 글자가 겹치면 둘 다 못 읽는다
- **그림·이펙트** (불·빛·파편·링) → **72% 까지 내려가도 된다.** 채팅 뒤로 색이 번지는 건 오히려 화면이 산다
- **배경** (사진 바탕·흰 종이·플래시) → **화면 전체.** 지금처럼 `inset:0` 은 안 건드린다

### 공식 가이드는 없다

찾아봤다. 유튜브가 내놓은 건 **Shorts 용 안전영역**(1080×1920 기준 888×1500,
위아래 11%씩)뿐이고 **라이브 채팅은 계산에 안 들어가 있다.** 라이브 고객센터
문서에도 오버레이 안전영역 이야기는 없다.

즉 **사장님 화면이 유일한 정답**이고, 위 표가 그걸 잰 것이다.
⚠️ 기기·앱 버전이 바뀌면 달라질 수 있으니 `SAFE_TOP`/`SAFE_BOT` 한 곳만 고치면
되게 둔다.

### 다른 위젯도 같은 문제다

연출만의 문제가 아니다. 편집기에서 놓는 위젯도 아래쪽이면 가린다.

- **📣 안내 전광판** — 기본 자리가 `top:1680` = **87.5%**. 채팅에 완전히 묻힌다
- 계좌 위젯 · 후원순위 · 게이지도 같은 기준으로 한 번 훑어야 한다

편집기에 **안전지대 가이드선**(위 6% / 아래 34%에 점선)을 그려 두면 앞으로도
잘못 놓을 일이 없다. 3단계에 넣는다.

## 2. "돈을 쐈구나" — 무엇이 부족한가

지금 연출은 **예쁘지만 조용하다.** 후원한 사람이 화면에서 자기 흔적을 못 찾는다.

| 지금 | 문제 |
|---|---|
| 금액이 카드에만, 작게 | 후원자가 **자기가 얼마 쐈는지** 화면에서 못 본다 |
| 이름도 카드에만 | 연출과 사람이 따로 논다 |
| 티어가 올라가면 **길어지기만** 한다 | 10만 1.8초 → 300만 7.5초. 화려함은 별로 안 는다 |
| 반짝임이 거의 없다 | 불·네온·금속은 있는데 **빛나는** 느낌이 없다 |

### 만들 부품 4개

전부 **공통 함수**로 만든다. 17개 연출이 한 줄로 갖다 쓰고, 티어가 세기를 정한다.

#### ① 금액 각인 `stamp(amount, at)`

착탄 프레임에 **금액이 숫자로 박힌다.** 이게 "돈을 쐈구나" 의 핵심이다.

- 큰 숫자 + `원`, 히트스톱과 같은 프레임에 눌리며 등장
- 금액대별로 색·크기가 다르다 (10만 흰금 → 300만 무지개 금속)
- ⚠️ 카드에 이미 있는 금액과 **겹치지 않게** — 카드는 착탄 뒤에 뜨니 시간이 어긋난다

#### ② 반짝임 밭 `sparkle(n, band)`

4갈래 별이 안전지대 안에서 시차를 두고 깜빡인다.

- `clip-path` 마름모 하나 + `opacity`/`scale` 만 — **가볍다**
- 개수 `n` 이 티어를 나타낸다 (10만 12개 → 300만 90개)

#### ③ 광택 쓸기 `sheen(el, at)`

글자·금속 위를 흰 띠가 한 번 지나간다. **VIP 에 이미 있는 기법**을 꺼내 공통으로.

#### ④ 금박 파편 `flakes(n)`

가즈아의 불티를 일반화한다. 회전 + 두 가지 금색 + 크기 편차.

### 티어 사다리 — 눈에 띄게 다르게

| 금액대 | 지금 | 바꿀 것 |
|---|---|---|
| 10~20만 | 1.8~2.8초 | 금액 각인 + 반짝임 12 |
| 30~50만 | 2.6~3.4초 | + 광택 쓸기 + 반짝임 30 + 테두리 발광 맥동 |
| 60~100만 | 2.6~4.6초 | + 금박 파편 + 반짝임 55 + 후원자 이름 |
| 200~300만 | 5.2~7.5초 | + 화면 전체 점유 + 여운 + 반짝임 90 |

### ⚠️ 렌더 예산

새 요소를 늘리면 **OBS 프레임이 떨어지고 그건 방송에 그대로 나간다.**

- 한 연출이 동시에 쓰는 DOM **200개 상한** (지금 최대는 MVP 74개 + 캔버스)
- `transform` · `opacity` · `filter` 만 움직인다 (레이아웃을 다시 잡게 하지 않는다)
- 파편·반짝임은 **하나의 `div` + 애니메이션**, 캔버스는 MVP 불꽃만 유지
- 검사에 **DOM 개수 상한**을 넣어 넘으면 실패시킨다

## 3. 순서

```
1단계  좌표 두 번 접힘 버그 + 안전지대  ← 한 번에. 17개 전부 자리가 바뀐다
   ↓   방송에 올려 확인 (글자 7개가 처음으로 화면에 나온다)
   ↓
2단계  편집기 안전지대 가이드선 + 안내 전광판 자리 옮기기
   ↓
3단계  부품 4개를 엔진에 추가 (연출은 아직 안 건드림)
   ↓
4단계  가즈아·방패에 먼저 붙여 세기 정하기  ← 착탄 때와 같은 방식
   ↓   ⏸ 여기서 멈추고 판단
   ↓
5단계  나머지 15개에 티어 사다리대로
```

**1단계가 가장 크고 가장 급하다.** 글자 7개가 안 보이는 채로 방송이 나가고 있다.

## 4. 검증

새 검사를 `tests/sigfx_test.js` 에 더한다. 지금 있는 가짜 DOM 이 좌표를 그대로
받아 적으므로 **자로 재듯 확인된다.**

| 검사 | 무엇을 지키나 |
|---|---|
| **안전지대** | 글자·읽어야 하는 요소가 전부 위 6% ~ 아래 66% 안에 있는가 (17개 전부) |
| **화면 밖 금지** | `top` 이 화면 높이를 넘는 요소가 하나도 없는가 — **이번 버그의 회귀 검사** |
| **좌표를 두 번 접지 않는가** | 설계값 × KY = 실제값 인가 (KY² 면 실패) |
| **배경은 그대로** | `inset:0` · `bottom:0` 은 여전히 화면 끝까지 가는가 |
| **DOM 예산** | 한 연출이 200개를 넘지 않는가 |
| **금액 각인** | 넘긴 금액이 화면에 그대로 나오는가 · 안 넘기면 조용히 건너뛰는가 |
